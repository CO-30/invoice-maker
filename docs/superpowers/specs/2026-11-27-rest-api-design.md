# REDSEAL 外部連携API 設計（v1.16.0・2026-11-27）

## 目的
外部のAIアシスタント（Muse など）が、REST API（と /mcp）で見積・請求・領収を自動連携できるようにする。
本人の指示：細かいことは聞かず最終段階まで（判断は Claude）、使用量を抑え、独立監査をする。
依頼文の［アプリ名］などは空欄だったため、このプロジェクトの REDSEAL を対象とした（Claude の判断）。

## 検討した方式
| 案 | 内容 | 判断 |
|---|---|---|
| A. GAS だけで REST | 追加サーバーなし | 不採用：GAS は Authorization ヘッダーを読めず、401/429 などの状態コードも返せず、PATCH/DELETE も受けられない |
| B. Cloudflare Workers（入口）＋ GAS（データ） | Worker が REST・認証・制限・Webhook・MCP。データと採番は従来のGAS | **採用**：無料枠・データは1か所・アプリの同期はそのまま |
| C. Workers＋D1 にデータを移す | 高速 | 不採用：アプリの同期と二重管理になる |

## 構成
外部AI → Worker（api/） → GAS（gas/Api.gs、POST本文の aiKey で認証） → スプレッドシート ←同期→ アプリ
- Durable Object（SQLite・無料枠）1個：APIキーのハッシュ、Idempotency-Key、Webhook、差分の控え。回数制限はメモリ内
- 採番・入力検査・排他は GAS（LockService）。既存の Ai.gs の処理を再利用

## 決まり（変えないもの・変えるもの）
- 本人が作った（確認・保存した）書類は、中身の変更も削除もできない
- 変更：削除は「AI下書き」に限り API で可能（依頼の CRUD に対応）。入金・失注の記録や PDF がある下書きは削除不可。削除は印を付ける方式（行は残る）。旧方式の GAS 直結 MCP には削除を足さない
- PDF の作成・送付はアプリで本人が行う

- アプリの同期：本人が保存・入金・失注の記録をした未送信の版は、削除の知らせが来ても消さずに送り直す。そのため、別の端末で本人が削除した書類も、未送信の変更がある端末からは復活する（本人の版を消さないことを優先）

## 認証
- APIキー `rsk_` ＋ 乱数32バイト。SHA-256 のハッシュだけを保存。表示は発行時の1回
- スコープ：read（documents:read）／write（documents:read＋documents:write）
- 認証結果は {type, id, scopes} の形。OAuth 2.0 はトークン検証を1つ足せば同じスコープで使える
- キーと Webhook の管理は管理トークン（環境変数 ADMIN_TOKEN・乱数で32文字以上、未満は無効）。アプリの設定画面から操作し、トークンは端末に保存しない
- URL のクエリにキーらしき項目があれば 400。https 以外は 403（localhost は開発用に許可）

## 差分取得と Webhook
- `updated_since` つき一覧は削除の印も返す。ただし updated_at はスマホで保存した時刻のため、圏外で保存した書類は後から古い時刻で届く。取りこぼしを避けるには、少し前から重ねて取る＋ときどき全件を取る
- Webhook は時刻に頼らず、全書類の控えと比べて検出（Cron 5分ごと＋APIで書いた直後）。署名 `X-Signature: sha256=<本文のHMAC-SHA256>`。本文は id・種類・番号・時刻のみ（宛名や金額は送らない）。失敗は間隔を空けて最大6回。重複配信はあり得るので受け側はイベント id で除く

## Idempotency-Key
書き込みの REST で任意。24時間保存。同じキー・同じ内容＝前の応答を再送。内容違い＝422。処理中＝409。GAS の結果が分からないとき（時間切れ等）＝以後 409（一覧で確認してから新しいキーで）。

## テスト
