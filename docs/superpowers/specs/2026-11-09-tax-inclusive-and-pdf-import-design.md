# 内税（税込入力）モード・他社書式PDF取り込み・発行者情報取り込み 設計書

- 日付：2026-11-09
- 対象：見積・請求書メーカー `index.html`（ベース v1.8.2）、`gas/Code.gs`・`gas/Code.generic.gs`
- 版：v1.10.0（v1.9.0 は別ファイル「写真から社判登録」で使用済み）

## 背景

iOS系の請求書アプリで作られた請求書PDF（A4縦、明細の金額が「(税込)」、見出しが「品 名」「金 額」と1文字ずつ離れている書式）を「📄 既存のPDFから作成」で読めるようにしたい。現状の解析では宛名しか取れず、日付・件名・明細が空になる。

さらに、この書式は明細が税込金額なので、アプリ側に「税込で入力する」計算方式が必要。あわせて、他の人がこのアプリを使い始めるときに自分のPDFから発行者情報を設定へ流し込めるようにする。

## 決定事項（本人確認済み）

| 項目 | 決定 |
|---|---|
| 税込明細の扱い | アプリに「内税（税込入力）」モードを追加する |
| 内税時の帳票合計欄 | 小計（税抜）→ 内消費税 → 合計（税込）の3段のまま |
| 切替場所 | 書類ごとに切替 ＋ 設定画面で新規作成時の既定を決める |
| 発行者情報の取り込み | 設定画面に「自分のPDFから発行者情報を取り込む」ボタン |
| ベース | GitHub の v1.8.2 |
| PDF解析方式 | 汎用パーサの強化（書式ごとのテンプレートは作らない） |

## 1. データ

### 書類（doc）
- `taxIn: boolean` を追加。`true`＝税込入力、`false`／未設定＝税抜入力（既存書類は未設定なので挙動不変）。
- `items[].price` の意味：税抜入力時は税抜単価、税込入力時は税込単価。項目は増やさない。
- 変換（見積→請求→領収）・改訂・複製は書類を深いコピーで作るため `taxIn` は自動で引き継ぐ。
- `newDoc()` は `settings.taxIn` を既定値にする。

### 設定（settings）
- `taxIn: boolean` を追加（既定 `false`）。`SKEYS` と `DEFAULT_SETTINGS` に加える。設定画面の既定税率の隣に「新規作成時の入力方法：税抜で入力／税込で入力」。

### GAS
- `DOC_COLS`（シートの列）は変更しない。`json` 列に書類全体が入るので `taxIn` も保存される。
- `calc_` を 2 と同じロジックに更新する（`Code.gs`・`Code.generic.gs` 両方、同一コード）。

## 2. 計算

`calc(d)`（index.html）と `calc_(d)`（GAS）は同じロジック：

```
amount = Σ (qty × price)
rate   = taxRate（%）
if !taxIn:
  sub = amount
  tax = round_by(d.rounding, sub × rate / 100)
  total = sub + tax
else:
  total = amount
  tax = round_by(d.rounding, total × rate / (100 + rate))
  sub = total − tax
return {sub, tax, total}
```

- `round_by`：`floor`（既定）／`round`／`ceil`。
- 検算：税込 ¥942,100・10%・切り捨て → tax 85,645、sub 856,455（元PDFと一致）。
- 税率 0 のとき：tax 0、sub＝total。

## 3. 編集画面

- 税率・端数の行に `<select id="taxIn">`：「税抜で入力」（value `0`）／「税込で入力」（value `1`）。`bindEdit`／`readEdit` に組み込む。
- 税込時の表示：
  - 明細行の単価欄 placeholder「単価（税込）」、行の金額ラベル「金額（税込）」。
  - 合計欄ラベル：「小計（税抜）」「内消費税（10%）」「合計（税込）」。税抜時は従来通り「小計」「消費税（10%）」「合計（税込）」。
- 切替時は金額を換算しない。切替イベントでトースト「金額はそのまま、計算方法だけ変わります」。
- 編集画面上の `renderItems` 内の行金額は qty×price（税込時は税込金額）で従来通り。

## 4. 帳票

### 請求書・明細型領収書（`renderSheet`）
- 税込時のみ：見出し「単価」→「単価(税込)」、「金額」→「金額(税込)」（同じ枠・小さめフォントで収める）。
- 合計欄：「小計」→「小計(税抜)」、「消費税（10％）」→「内消費税（10％）」。「合計」は変更なし。
- 座標・罫線・塗りは変更しない。

### 見積書（`renderEstimate`）
- 同じ扱い（見出しの「単価」「金額」、合計欄のラベル）。「合計金額 ¥…（税込）」は変更なし。

### 簡易型領収書（`renderReceiptSimple`）
- 変更なし（「税込・内消費税」表示は `calc` の値を使うので自動で正しい）。

### 送付文面
- `{金額}` は `calc().total`（税込）のまま。変更なし。

## 5. PDF取り込み（`parseInvoicePdfText` の強化）

入力は従来通り pdf.js の textContent（`{str,x,y,w}`）。追加・変更点：

1. **行の組み立て**：従来の y 近傍（6.5pt）でのグルーピングは維持。各行に `joined`（文字片を空白なしで結合した文字列）を持たせ、ラベル判定は `joined` で行う。
2. **日付**：`(\d{4})\s*[年/.\-]\s*(\d{1,2})\s*[月/.\-]\s*(\d{1,2})` のように空白を許容。ラベル付き（見積日・請求日・発行日）を優先し、なければ最初の年月日。
3. **明細見出し**：`joined` に「摘要」または「品名」を含み、かつ「金額」を含む行を見出し行とする。列 x は、見出し語の先頭文字片の x（「数量」「単価」「金額」「摘要（右端の備考列）」）。「月日」または「日付」があれば日付列とする。
4. **件名**：「件名」ラベルが無い場合、行頭が `CL`／`現場`／`現場名`／`工事名`／`物件名`／`案件名` のいずれか（単独の文字片）で、後ろに文字がある最初の行の後ろを件名にする。
5. **明細行**：
   - `¥`／`\`／`円` 単独の文字片は無視。
   - 数量列：数値の直後に単位候補（個・式・枚・台・時間・日・ヶ月・か月・本・m・㎡・m2・回・人・セット・箇所・ケ所・基・袋・缶・kg・L）が続けば数量＋単位。
   - 単価列が空で金額があれば 単価＝金額÷数量（整数なら整数、割り切れなければ小数2桁）。
   - 右端の備考列（見出し「摘要」が品名列と別にある場合）に文字があれば、品名の後ろに空白1つで連結。
   - 明細の日付列に「10/16」「10 16」等があれば書類日付の年を補って `YYYY-MM-DD`。
   - 明細行の y 近傍に「(税込)」の文字片があれば、その文字片は品名に入れない。
6. **税込判定**（`taxIn`）：次のいずれかで `true`。
   - 明細の見出し〜小計の範囲に「税込」を含む文字片がある。
   - 書類内の「合計」「税込合計」「請求金額」等の最大金額 ＝ Σ(数量×単価)（±1円）で、かつ消費税額が 0 でない。
   - いずれでもなければ `false`。
7. **税率**：従来の「消費税（10%）」に加えて「10%対象」の形式も読む。
8. **戻り値**：`{..., taxIn}` を追加。`importPdf` で `d.taxIn=p.taxIn`。
9. **既存書式**：アプリ自身の請求書（「摘要／数量／単価／金額」「御中」「件名：」「請求No.」）と お見積書.xlsx 準拠見積書の解析結果が変わらないことをテストで確認する。

## 6. 発行者情報の取り込み（設定画面）

- 設定画面の発行者情報カードに「📄 自分のPDFから発行者情報を取り込む」（`<input type=file accept=pdf>`）。
- 新関数 `parseIssuerPdfText(items)`：
  - 対象領域：ページ上部（明細見出しより上）で、x がページ中央（約 297pt）より右の文字片。該当がなければページ上部全体。
  - 郵便番号：`〒?\s*(\d{3})\s*-?\s*(\d{4})` → `zip`。
  - 住所：郵便番号行の次の行から、TEL／メール／登録番号の行まで（最大2行）→ `addr1`／`addr2`。
  - TEL：`(TEL|電話)?\s*:?\s*(0\d{1,4}-\d{1,4}-\d{3,4})` → `tel`。
  - メール：`[\w.+-]+@[\w.-]+\.\w+` → `email`。
  - 登録番号：`T\d{13}` → `regno`。
  - 屋号／会社名：郵便番号行の直前の行（空でなければ）。なければ「株式会社／有限会社／合同会社」を含む行。
  - 振込先（ページ全体から）：「銀行／信用金庫／信用組合／信金／農協／JA／ゆうちょ」を含む行 → `bank`（支店名まで同じ行に入れる）、「普通／当座／貯蓄」→ `bankType`、その行の 5〜8桁の数字 → `bankNo`、「口座名義／名義／カナ」の後ろ → `bankName`。
- 取り込み後：見つかった項目だけ `s_*` の入力欄に入れる（空の項目は触らない）。自動保存はしない。トースト「○件を入力欄に入れました。確認して保存してください」。何も見つからなければ「発行者情報を読み取れませんでした」。

## 7. 使い方ページ

`<details>` を3つ追加：
- 「税込の金額で入力したい」：入力方法の切替、帳票の見え方、既定の設定。
- 「他のアプリで作ったPDFを取り込む」：対応する目安（文字が選択できるPDF、明細表に数量・金額の見出し）、税込は自動判定、読めなかった項目は手で補う。
- 「設定を自分のPDFから取り込む」：設定画面のボタン、確認して保存。

## 8. テスト

- `tests/` に node スクリプト（`npm test` 不要、`node tests/run.mjs` で実行）。`index.html` から `parseInvoicePdfText`／`parseIssuerPdfText`／`calc` を正規表現で切り出して評価する（既存コードの関数境界 `function …(){ … }\n` を利用）。
- fixtures：
  - `tests/fixtures/ios-invoice.json`：今回のPDFと同じ座標構造で、社名・住所・電話・口座・金額を**ダミーに置き換えた**文字片リスト。実データは入れない。
  - `tests/fixtures/app-invoice.json`：アプリ自身の請求書レイアウト（`renderSheet` の座標）を模した文字片リスト。
  - `tests/fixtures/app-estimate.json`：お見積書.xlsx準拠見積書を模した文字片リスト。
- 検証内容：
  - iOS書式：type=invoice、client、honor=様、date=2026-10-16、subject=「楚辺 新築工事」相当のダミー、items 3行（qty・unit・price）、taxIn=true、合計検算。
  - 既存2書式：従来の期待値のまま（回帰）。
  - calc：税抜・税込それぞれ floor/round/ceil、税率0。
  - 発行者情報：ダミー fixture から zip・addr・tel・bank 各項目。
- 実機確認（本人）：iPhone で実PDFを取り込み→プレビュー→PDF作成。

## 9. 変更しないもの

- 帳票の座標・罫線・社判の処理。
- GAS のシート列構成。
- CSV 書き出し（小計・消費税・合計は `calc` の値なので自動で正しくなる）。
- JSON バックアップ／復元（`taxIn` は書類・設定に含まれて保存される）。

## 10. 互換性

- `taxIn` 未設定の書類・設定は税抜として扱う。古い版で作った書類をそのまま開ける。
- 新版で作った税込書類を v1.8.x で開くと税抜として計算される（合計が変わる）。使い方ページに「端末ごとに更新を」の一文を添える。
